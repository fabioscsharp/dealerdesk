HOW TO RELEASE DEALERDESK
=========================

1. Build on your machine (see README)
2. Test it a bit: add a car, do a quote, sell a car, check the invoice looks right.
   PUT THE DATA FILES BACK AFTERWARDS!!
3. On \\fileserver01\apps\dealerdesk\ rename dealerdesk to dealerdesk.old
4. Copy the new dealerdesk binary there
5. Email the showrooms that a new version is out
6. If something breaks, copy dealerdesk.old back

Last release: 2.3 (2021-04-08)  - P.


ADDED 2026-11-16: RELEASE 2.4 (fleet discount, TICKET-142)
==========================================================

Before step 1 above, BACK UP THE DATA: copy the whole data folder on the file server
(customers.dat, invoices.dat, stock.dat, next_ids.dat) somewhere safe.

Build with `make` and run `make test` instead of "test it a bit" (see README, Build and test).

ROLLBACK WARNING for 2.4: dealerdesk.old (2.3) can read the 2.4 data files, but the first
time it saves anything (adding, reserving or selling) it rewrites the files in the old
format. That silently drops:
  - every customer's fleet flag
  - the fleet discount amount on every invoice (totals stay correct)
After a rollback, either restore the backup taken above before going back to 2.4, or
flag the fleet customers again (Customers > 4) once 2.4 is back.

Release: 2.4


UPDATE 2026-11-16 (spec 003): automatic checks and releases

The steps above are unchanged and still apply to deploying on the file server. Building and
testing are now automatic; see RELEASING.md for the details.

  - Every pull request and every push to master runs the checks (make test, make test-mutation,
    make test-compat) on GitHub Actions: .github/workflows/ci.yml, or locally: sh scripts/check.sh
  - A release is made by the Release workflow (.github/workflows/release.yml): push a plain
    version tag (for example 2.5), or run it by hand from the Actions page with the version.
    It publishes a GitHub Release with dealerdesk-VERSION.zip (binary and sample data), a
    SHA256 file and notes. The version must equal the one shown in the app header (screen.c).
  - That binary is built for Linux. Steps 1 and 2 above (build and test) are now done by the
    workflows. Steps 3 to 6 (rename to dealerdesk.old, copy the new binary, e-mail the
    showrooms, roll back) are still done by hand, and BACK UP THE DATA before step 3. The
    rollback warning for 2.4 above applies to every release after it.
